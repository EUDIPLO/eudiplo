# Backend Dependency Audit

## Scope

This is an incremental audit of backend source imports against the target in [Backend Architecture](./backend-architecture.md). A framework or infrastructure import is valid when it belongs to an inbound adapter, infrastructure adapter, or composition/bootstrap module. The presence of a legacy `*.service.ts` file alone does not establish its architectural role.

## Verification

- Incremental boundary tests fail when enforced application/domain/port paths add forbidden inward dependencies, including resolved local dependencies and barrel paths.
- Entity-backed repository ports are currently listed as explicit transitional exceptions in `test/architecture/dependency-rules.ts`; each must be replaced with a plain model contract before final sign-off.
- Endpoint repository and deferred-lifecycle exceptions were removed on 2026-09-28. Four repository exceptions remain: tenant, general credential configuration, credential-management configuration, and issuance configuration.
- A broad lexical scan still reports many valid adapter, controller, module, entity, migration, and legacy service imports. The list must be reclassified after each migration batch; lexical matches alone are not violations.
- Task 25 remains **in progress**. The known legacy groups above are not accepted as a claim that the final audit is clean. Follow-up refactors should remove each group or document a specific reason and owner before final sign-off.

## Recommended Next Audit Batch

Prioritize OID4VCI orchestration and deferred issuance. Characterize protocol error bodies/headers, DPoP/token validation order, nonce consumption, tenant scope, webhook timing, and deferred transaction behavior before extracting a focused use case. Re-run both SQLite and PostgreSQL adapter contracts for any persistence change.
